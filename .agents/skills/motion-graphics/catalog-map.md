# Director → 目录块映射（优先复用）

Builder 的**默认行为是组合现有 HF 目录块，而非手动编写。** `npx hyperframes add <block>` 将块的源代码放入 `compositions/` 中；Builder 然后**原地定制**——大多数块将其内容/数据烘焙到自己的脚本中（只有少数暴露 CSS 变量参数），所以复用 = **添加 + 编辑**，而非纯变量注入。仅手动编写（a）没有块覆盖的空白和（b）asset-fusion 适配器绑定。

在将意图分类为类别后，**Director 在镜头计划 IR 中指定块以及要定制的内容**：

```jsonc
"content": { "block": "data-chart", "customize": { "data": [...], "headline": "…", "palette": ["…"] } }
```

## 复用机制

- `npx hyperframes add <block>` → 源代码放入 `compositions/<block>.html`；内联或通过 `data-composition-src` 引用；原地定制内容/数据/调色板/位置。
- 块以固定画布提供（1920×1080 / 1080×1920 / 1080×1080）— 匹配或适配。
- 块已遵循 HF 约定（暂停的时间线、seek）— 保持原样。

## Asset-fusion：借用 + 全新（唯一真正的新 IP）

借用 `north-korea-locked-down` 的标注_语言_；全新的是 RWA 融合_逻辑_（参见 RWA 研究）：

1. 分类数据类型；读取资产的**几何适配性** — 线性 → 时间线/仪表、体积/纹理 → 饼图、高度 → 条形图、容器 → 分解视图。
2. **`element_positions`** — 测量资产特征（中心/范围/安全区/避让区）。这是逆向工程步骤（视觉）；在原型中为手动估算。
3. **从资产取色**（从不使用通用 #FFF/#000）。
4. **两层** — 资产（z0，全出血）+ 数据图形融合到其几何形状上（z1+），由 `element_positions` 锚定；连接器/手绘线将数据物理绑定到资产；资产保持可见。
